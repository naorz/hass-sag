# UX Patterns for hass-sag CLI

## Menu UX Rules

### Disabled Items
- **Never remove menu items** — always show what the tool can do, but disable with an explanation when prerequisites are missing.
- Disabled message format: `"Do X first (Parent Menu → Step Name)"`
- Examples:
  - No token: `"Configure a token first (Configure CF Token)"`
  - No P12: `"Generate PKCS#12 first (mTLS & Certificates → Generate PKCS#12)"`
  - No key+pem: `"Generate Identity first (Key + CSR)"`
- `disabledWhen` is evaluated at render time (each menu loop), so items unlock dynamically.

### Item Order
- **Most common action first** (e.g., Validate before Configure when token exists)
- **Destructive actions last** (e.g., Clear Token, Delete Rule)
- **Back option always last** in sub-menus

### Descriptions
- Every menu item must have a description explaining what it does
- Use plain language, not technical jargon
- Mention what the user can verify after running it

### Badges
- Dynamic status indicators appended to menu labels: `" [✓ token]"`, `" [no token]"`
- Evaluated at render time via `badge?: () => string`

### Numbered Lists
- WAF rules, certificates, and other selectable lists must be numbered (1, 2, 3...)
- Numbers are consistent across views (view, toggle, delete, reorder)
- Users reference items by number

## Error Handling

### Menu Error Recovery
- Wrap action execution in try/catch in `Menu.show()`
- On error: print the error message, then `"Press Enter to return to menu"`
- Never crash back to terminal — always return to menu gracefully

### CF API Errors
- Only treat `PermissionDeniedError` (403) and `AuthenticationError` (401) as permission errors
- `NotFoundError` (404) = resource doesn't exist yet, not a permission problem
- Don't swallow errors with catch-all `catch { return undefined }` — only catch specific expected errors

### Validation Errors
- Zone ID must be a 32-char hex string — validate before use
- If stored config has invalid values, clean them and fall through to .env
- Show clear error with format example: `"Must be a 32-char hex string (e.g. 023e105f...)"`

## File Dependencies

### Check Before Use
- Menu items that need specific files should be disabled when those files don't exist
- Chain: Generate Identity → Generate P12 → Generate Apple Profile → Sign Profile
- Connection test needs key + pem
- Cert install needs p12
- `disabledWhen` checks `fs.existsSync()` at render time

### Generated File Expectations
- `client.key` — private key (generated by openssl)
- `client.pem` — signed cert from CF (user saves or API returns)
- `device-cert.p12` — PKCS12 bundle (key + cert, empty password, `-legacy` flag)
- `apple-secure.mobileconfig` — Apple config profile with embedded P12

## CF API Operations

### Always Print Context
- Before every CF API call, print `[CF API] What this operation does...`
- After the description, print `Verify: Dashboard path where user can check the result`
- Example: `[CF API] Creating WAF rule...` / `Verify: Security → WAF → Custom rules`

### Token Management
- Token resolution: config → .env → process.env → interactive prompt
- Auto-configure on startup if credentials exist
- Validate permissions against 5 scopes: Zone Read, SSL & Certificates Edit, Firewall Services Edit, Zone WAF Edit, Zone Settings Edit

## Platform Compatibility

### P12 Generation
- OpenSSL 3.x requires `-legacy` flag for macOS Keychain compatibility
- Without it: `MAC verification failed during PKCS12 import (wrong password?)`
- Empty password: `-passout pass:` for generation, `-P ""` for import

### Connection Tests
- Always run two tests: WITH cert (expect 200) and WITHOUT cert (expect 403)
- Show the curl commands so users can reproduce manually
- Explain what each result means and how to fix failures

## Token Security
- Token is stored locally only — never uploaded, auto-added to .gitignore
- Explain this when prompting: `"this value is only used locally — it is never sent anywhere by this tool"`
- After save: `"Stored locally in .env only — never uploaded, auto-added to .gitignore"`

## General Principles
- Free tier awareness: show `X/5 rule slots used` for WAF
- mTLS rule analysis: detect rules by expression content, suggest fixes
- Show manual verification paths for every automated action
- Graceful degradation: skip CF steps when no token, explain what was skipped and why
